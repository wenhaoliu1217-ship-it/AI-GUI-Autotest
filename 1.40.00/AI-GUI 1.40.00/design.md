# 1.40.00 界面设计约定

## 产品目标

默认用户完全不懂编程、自动化测试或模型接入。AI 先询问要测试的网址；用户可只发网址，也可在同一条消息中写“网址 + 测试要求”。系统识别后始终留在同一工作台，持续承载网站画面、任务过程、审批、结果和后续对话。

1.40.00 借鉴 Browser Use Cloud 的工作台连续性与模型切换效率，但不复制其完整功能集合，不改变“通用网站 GUI 自动测试助手”的产品初衷。

## 页面结构

- 普通导航：开始测试、测试记录、模型中心、高级设置。
- 开始测试：AI 首条消息询问网址；同一输入框支持网址和自然语言要求一起发送。
- 测试准备：对话/要求与网站识别结果并列，网站画面区域保持固定，不另开任务结果页面。
- 运行中：持续更新真实网站画面、AI 说明、审批和执行状态；技术证据保持折叠。
- 结果：先给普通中文结论，用户可在原工作台继续追加要求或发起下一次运行。
- 模型中心：保存多个 Provider/模型档案，显示名称、验证状态和当前模型；工作台提供快速切换。
- 模型中心高级连接：协议、Base URL、价格等低频技术字段默认折叠。
- 高级设置：保留项目、环境、场景、固定计划、65 项验收及其他专业能力。

## 数据与安全

- 模型档案元数据与 API Key 分开保存。
- API Key 使用 Windows DPAPI 按当前系统用户加密，前端 API 永不返回密钥明文。
- 模型切换不会打断正在执行的浏览器动作；新的运行读取当前选中的模型。
- 未配置或未验证模型时，允许完成网址识别和只读扫描，但开始 AI Agent 前必须明确引导到模型中心。
- 密码、验证码、付款、账号安全修改和非测试数据删除始终由用户本人处理。

## 视觉规则

- 设计风格：现代极简、可靠克制的工具型工作台，接近专业 Agent 产品而不是营销站。
- 延续蓝灰品牌色、深色侧栏、白色工作面板和紧凑状态提示，不做像素级模仿。
- 不使用渐变、装饰插图、动画背景或虚假浏览器外框。
- 强调色只用于主要动作、当前状态与链接；风险为红色，成功为绿色。
- 桌面端使用对话/任务区与网站画面双栏；移动端按“对话 → 网站状态”单列排列，禁止横向滚动。
- 所有交互保留清晰的 hover、focus-visible、active、disabled、loading、error、success 状态。

## 文案规则

- 普通流程不暴露 storageState、DOM、Playwright、L0-L3 等内部术语。
- 首条消息明确说明可以把网址和要求写在一起，避免强制多轮问答。
- AI 必须提前说明登录、写入批准、截图授权和付款边界。
- 模型中心用“服务商、模型名称、档案、验证、当前模型”等用户可理解的词；技术连接项放入折叠区。
