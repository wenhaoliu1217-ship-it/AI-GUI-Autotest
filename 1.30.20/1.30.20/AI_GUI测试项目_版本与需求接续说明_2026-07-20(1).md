## 4. 当前 V.2 已经具备的真实能力

### 4.1 前端管理端

- 总览、项目接入、AI 模型设置、新建测试、执行详情、历史报告、报告详情页面。
- 项目接入页支持 Base URL、允许域名、禁止动作、L0～L3 接入等级、最大步骤、运行时间和模型调用上限。
- L1 项目支持导入 Playwright `storageState`，也支持启动受控浏览器完成交互登录录制；录制完成后复用 DPAPI 存储接口。
- 登录态页面只展示域名、数量、加密方式和过期状态，不呈现 Cookie 值。
- 已接入项目可直接启动真实只读兼容性扫描；扫描最多遍历 6 个允许域名内安全 GET 页面，不点击、不填写、不提交，并展示 DOM／ARIA、认证、Canvas／WebGL、iframe、SPA／异步模式、导航、控制台／网络异常、稳定／视觉／自适应／人工区域、接入等级和推荐配置。
- 用户输入场景名称、目标 URL、执行角色、前置条件、自然语言流程和预期结果。
- 支持本地规则规划与用户配置的 AI 模型规划。
- AI 配置支持 OpenAI Responses API 和兼容 Chat Completions 服务。
- API Key 当前只保存在页面内存并随请求发送，不写入源码或本地配置文件。
- 计划生成后必须人工审核，允许修改动作、定位器和断言。
- 无法解析的自然语言会提示补充，不再伪造成功结果。
- 历史报告来自真实后端运行记录，不使用 Mock 运行结果；支持逐条选择、全选、取消选择和删除选中报告，删除前有不可恢复确认。
- 运行详情和报告页展示每步执行模式、稳定性等级、动作前后截图、页面事实、运行时异常、结构化问题及生成代码。
- 管理端启动测试时使用后台运行模式，执行页轮询真实步骤进度；排队／运行中的任务可以请求停止，当前浏览器动作结束后安全关闭并保存已有证据。
- 新建测试页显式区分“固定计划执行”和“逐步 Agent 探索”；逐步模式只在模型连接成功后启用，并展示每次决策、Token、耗时、进展判断和可选成本估算。
- 问题支持确认／驳回；生成的 `.spec.ts` 可预览和下载；稳定／自适应入口受稳定性等级门禁控制。

### 4.2 后端与执行器

- FastAPI 本地服务。
- `ProjectConfig`、`EnvironmentConfig`、`ScenarioConfig`、`CompatibilityReport` 和审计记录使用本地文件持久化；一键运行版默认保存在 `Windows一键运行\data\projects`。
- 已有项目创建／读取／更新／删除 API、Environment／Scenario API 和项目审计记录；Environment／Scenario 已有完整前端创建、选择、编辑和运行关联闭环。
- 已有运行历史批量删除 API；删除前会校验整批运行编号和工件目录，校验全部通过后才删除所选运行的完整工件目录，单批最多 500 条。
- `storageState` 在导入前校验 Cookie／Origin 域名和 2 MB／数量上限，使用 Windows DPAPI CurrentUser 加密为 `storage-state.dpapi`；不落盘明文。
- 交互登录录制由后台线程持有 Playwright 浏览器，支持完成／取消／超时；只有用户点击完成后才提取并加密保存 `storageState`。
- 扫描和选择项目后的真实执行会加载该项目登录态；完全过期时拒绝运行并要求重新导入。
- 兼容性扫描只执行页面导航和结构观察，不点击、不填写、不提交，不采集密码、Cookie 或完整 DOM。
- 项目允许域名、最大步骤、总运行时限和模型调用上限均参与真实执行约束；Environment 的网络忽略规则、Viewport、设备缩放和密钥引用按单次运行加载。
- Playwright Chromium 真实浏览器执行。
- 已有持久 Run Orchestrator 第一阶段：运行编号在启动前生成，状态按 `queued`／`running`／明确终态写入 `run-state.json`，每步完成后更新轨迹；支持取消 API、项目总时长限制和异常退出恢复为 `system_error`。
- 已有逐步 DOM Agent Planner：以不可变 Scenario、最新脱敏 Observation 和历史轨迹为输入，每次只返回一个受 Pydantic Schema 约束的动作／完成／阻塞决策；Playwright 执行后重新观察。已强制最大步骤、最长时间、最大模型调用、连续三次无进展停止和禁止动作策略。
- 当前支持的动作：`navigate`、`click`、`fill`、`select`、`wait_for`、`screenshot`、`clear`、`check`、`uncheck`、`hover`、`scroll`、`back`、`reload`、`press`、`visual_click`、`bridge_click`。
- 当前支持的断言：页面到达、可见／不可见、文本包含、URL 包含、值相等、数量相等。
- 基于域名策略限制跨域访问。
- 支持环境变量／秘密引用和日志脱敏。
- 密码、Token 等敏感输入在规则规划和 AI 计划校验后强制转换为密钥引用；不把用户提供的密码写入计划描述和生成代码。
- 每一步采集动作前后截图、URL、标题、裁剪后的 DOM、ARIA 摘要、Console error、未捕获异常、失败请求和 HTTP 4xx／5xx。
- `visual_click` 使用目标 Canvas 内的相对坐标并检查边界；`bridge_click` 通过 `window.__WEB_AI_TEST__` 的语义目标 ID 获取运行时位置，再由 Playwright 点击和读取选中状态。
- 每次运行生成唯一运行编号、计划快照、步骤结果、截图、事件日志、Trace、JSON、Markdown、HTML 报告和生成的 `.spec.ts`。
- 失败原因按 locator、timeout、navigation、security、assertion、unknown 等类别输出启发式提示。
- 根据执行错误、断言失败和运行时异常生成结构化 Finding，包含类别、严重度、置信度、实际／预期、事实、推断、证据和审核状态。
- Test Compiler 优先输出 Playwright 语义 locator，对步骤和测试标注 A～D；视觉代码使用 Canvas 相对位置，桥接代码使用语义 ID，不固化探索时绝对屏幕坐标。
- 回放 API 明确区分 `stable` 和 `adaptive` 并检查支持等级；当前 adaptive 仍复用固定计划执行器，尚未接入真实 Computer Use 动态找回。

## 5. 2026-07-19 至 2026-07-20 已处理的问题

1. **启动器打不开**  
   原因包括 Windows PowerShell 5 对无 BOM UTF-8 脚本的兼容问题。已改为兼容的启动逻辑，并验证 BAT 能启动服务。

2. **V.2 缺少 `gui_agent.artifacts` 模块**  
   V.2 打包漏掉截图／报告模块，导致 `ModuleNotFoundError`。已补齐源码版和一键运行版，并加强启动前模块完整性检查。

3. **重复预期被误报**  
   自然语言流程中已经包含断言、预期结果再次出现相同断言时，已改为静默去重，不再阻止审核。

4. **同一流程有时成功、有时超时失败**  
   原因是外部网站响应波动和原固定 10 秒导航阈值。现在默认导航超时为 30 秒，并以页面已收到响应为基础，再由后续 locator／断言验证可操作性，降低第三方资源加载造成的假失败。

5. **失败后截图为空、截图按钮失效**  
   失败导航时普通 Playwright 截图会继续等待页面加载。现增加 CDP 底层截图与停止加载兜底；失败步骤可以真实保存 PNG。

6. **截图按钮依赖 `window.open`**  
   已改为原生 `<a target="_blank">`，降低弹窗拦截和点击失效问题。

7. **断言失败截图没有入口**  
   后端已有断言截图，前端现已映射并展示“失败截图”。

8. **报告详情布局混乱**  
   已把步骤说明、状态、耗时、错误和证据重新分层；长错误自动换行，报告诊断栏在宽屏固定、窄屏自动下移。

9. **文件整理误操作风险**  
   之前曾发生用户认为“动了其他文件”的问题。后续 AI 只能修改当前权威 V.2 目录和用户明确点名的文件，不得移动团队资料、签约资料或其他项目文件夹。

10. **企业项目接入、登录态与兼容性扫描缺失**  
    已新增项目持久化、安全边界、L0～L3 配置模型、DPAPI 加密 `storageState` 导入、产品内交互登录录制和真实只读扫描闭环。扫描结果来自真实 Chromium 页面观察，不由前端伪造。完整接入等级自动判定仍未实现。

11. **运行证据不足**  
    已新增 Observation Collector，每一步同时保存动作前／动作后截图、URL、标题、裁剪 DOM、ARIA 摘要、Console error、未捕获异常、失败请求和 HTTP 4xx／5xx，并在报告中区分事实与启发式推断。

## 9. 企业需求中特别不能漏掉的能力

### 9.1 分级接入

- L0 黑盒：无源码改动，DOM／Canvas 探索、视觉操作、报告、基础测试生成。
- L1 配置增强：无源码改动，增加登录态、固定环境、允许域名、网络规则。
- L2 可测试 DOM：可选增加 `data-testid`、ARIA 和稳定 locator。
- L3 Canvas Bridge：可选提供实体、相机、图层、选中状态和加载状态接口。

拒绝 L2／L3 时仍必须允许继续使用 L0／L1，不能把改造被测应用当成首次使用前置条件。

### 9.2 三种执行模式

每一步都要记录：

- `locator`：AI 选语义目标，Playwright 用 DOM／Accessibility locator 执行。
- `visual`：Computer Use／视觉模型看截图并提出目标，最终仍由 Playwright 执行动作。
- `app_bridge`：Canvas Bridge 提供语义对象或位置，最终仍由 Playwright 执行或验证。

禁止把探索时的一次性绝对屏幕坐标直接保存为长期回归 locator。

### 9.3 A～D 稳定性等级

- A：确定性，可作为稳定回放和 CI 候选。
- B：相对稳定，可回放但必须展示风险。
- C：需要 Computer Use 自适应寻找，仅用于自适应回放。
- D：暂不可自动化，只生成说明和人工步骤。

测试整体等级取所有步骤中的最低等级。

### 9.4 稳定与自适应回放必须分开

- 稳定回放默认不调用 AI／Computer Use 决定动作。
- 自适应回放只能由用户显式启用。
- 稳定回放失败后不得静默切换为自适应模式。
- 自适应失败必须明确失败或请求人工确认，不能猜测后继续。

## 13. API Key 更换与安全注意事项

- 本文和项目文件中不得复制旧 Key，也不得记录新 Key。

### 19.1 回答正确或基本正确的部分

1. “当时版本主要把自然语言转换为固定操作步骤，后续再做 AI 动态决策”是正确的。V2 只有 `generic_planner.py` 固定规则规划和 `ai_provider.py` 一次性生成完整 `TestPlan`，没有 Observation→Planner→单动作→再观察的逐步 Agent。

4. “本地规则规划阶段不读取页面 DOM”正确；V2 的规则规划器只解析用户填写的流程文本。

### 19.2 需要修正的部分

1. “执行角色、前置条件仅用于存储，不关联 AI”不准确。V2 的规则规划中二者主要写入计划元数据，不直接控制浏览器动作；但 AI 计划接口会把 `role` 和 `preconditions` 放进模型 Prompt，它们可能影响 AI 生成结果。更准确的说法是：**二者尚未形成强制运行策略，但在 AI 规划模式下会作为上下文参与规划。**
2. “AI 行为默认从客户视角出发”没有代码依据。V2 系统提示只定义“GUI 自动化测试规划器”，没有固定客户视角；未填写角色时就是未指定角色，不能对外宣称默认客户身份。
3. “接入 AI 模型后会读取 DOM 元素”不正确。V2 的 AI 计划生成仍只接收名称、URL、流程、角色、前置条件和预期结果，并不启动浏览器读取 DOM。真正读取 DOM／Accessibility 并逐步决策的是后来 `1.25.00` 增加的 Agent 模式。
