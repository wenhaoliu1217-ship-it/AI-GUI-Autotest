## 3. P0 更新需求

### GAE-GUI-01：placeholder 原生定位与观察

当前问题：登录租户、用户名、密码和地图搜索主要依赖 placeholder；现有 Locator 只能使用 role、label、test ID、CSS 和文本。

更新范围：

- Locator Schema 增加 `placeholder`。
- Playwright 解析使用 `get_by_placeholder`。
- Observation DOM 摘要采集 placeholder，但不得采集密码或输入值。
- Agent Prompt、AI 计划 Schema、规则计划审核器、前端计划编辑器和代码生成器同步支持。
- 定位优先级保持语义优先，placeholder 位于 label 之后、CSS 之前。

验收标准：

- 不手改 CSS 即可生成并执行租户、用户名、密码三项登录定位。
- 密码仍只使用 `value_from_secret`，报告、截图、Trace 和模型上下文无明文。
- 同一登录场景连续运行 5 次，定位成功率 100%。

### GAE-GUI-02：表格行与容器作用域定位

当前问题：装备智能体、想定和运行记录存在大量行内图标；“第一个图标／第五个红色图标”会随排序、分页和权限变化而误操作。

更新范围：

- 支持 `within`／父容器定位，以模型名、想定名或运行名所在行作为作用域。
- 支持 `title`、稳定 tooltip、ARIA name 和目标行内按钮组合定位。
- 支持表格列名、行文本和目标控件的结构化组合；不得默认依赖全局 `nth`。
- 报告保存完整作用域定位链和最终匹配数量。

验收标准：

- 在包含至少 10 行且经过排序／翻页的列表中，修改、详情、复制和删除入口均命中指定业务对象。
- 匹配 0 个或多个候选时明确拒绝，不执行猜测点击。
- 删除确认只能针对测试前缀对象，错误对象操作次数为 0。

### GAE-GUI-03：安全文件上传与测试文件仓库

当前问题：目标系统需要 JSON、ZIP、HGT 和缩略图上传；当前动作白名单没有文件上传动作。

更新范围：

- 增加显式 `upload_file` 动作和 Playwright `set_input_files` 执行。
- 增加项目级测试文件仓库，只允许引用登记后的相对路径或文件 ID。
- 保存文件名、类型、大小和 SHA-256，不把任意宿主机路径写入计划。
- 支持合法、非法、空文件、扩展名错误、尺寸错误和大小边界用例。
- 上传属于副作用动作，可按项目策略进入人工确认。

验收标准：

- JSON、ZIP、HGT、图片各至少一个合法和一个非法样例可重复执行。
- Runner 不能读取测试文件仓库和单次运行目录之外的任意用户文件。
- 报告包含文件元数据、页面结果、请求结果和清理状态，不包含文件中的敏感业务内容。

### GAE-GUI-04：受控下载与下载内容校验

当前问题：仿真数据、评估数据和批量导出是核心测试点；当前本地隔离 Runner 禁止浏览器下载，也没有 download 动作。

更新范围：

- 增加显式 `download` 动作，只允许写入单次运行的 `downloads` 工件目录。
- 监听 Playwright download，保存建议文件名、实际文件名、大小、MIME 和 SHA-256。
- 支持 ZIP／JSON／CSV 等结构和关键字段校验。
- 非显式下载、路径穿越、超限文件和危险扩展名必须拒绝或隔离。
- 下载文件纳入保留期、手动删除和删除审计。

验收标准：

- 仿真数据和评估数据可下载、可校验、可在报告中追溯。
- 下载目录之外无新增文件；文件名路径穿越测试全部拒绝。
- 下载失败必须区分权限、服务端、网络、超时和格式错误。

### GAE-GUI-05：异步业务状态等待与状态机断言

当前问题：想定启动／停止、仿真运行、训练和大文件处理均为异步过程，固定等待不能证明业务完成。

更新范围：

- 增加按可见状态、接口状态或 Bridge 状态轮询的 `wait_until` 能力。
- 支持状态序列断言，例如 `未启动 -> 启动中 -> 运行中 -> 已完成`。
- 配置轮询间隔、最长业务时限、允许的中间状态和失败状态。
- 保存状态变化时间线、关联业务 ID、请求和截图。
- 超时后停止轮询并保留证据，不重复触发启动动作。

验收标准：

- 想定启动、停止和仿真完成可以用状态机而非固定 sleep 判定。
- 重复状态、非法倒退、服务断连和超时均生成明确 Finding。
- 长任务不受单步 30 秒默认值误判，仍受项目总时限约束。

### GAE-GUI-06：业务测试数据生命周期

当前问题：完整闭环需要创建、复制、上传、启动、下载和删除，但现有指导书尚未提供可重复数据和清理协议。

更新范围：

- 每次运行生成唯一测试前缀并记录创建对象 ID。
- 支持场景级 setup／cleanup 阶段和失败后的补偿清理。
- 删除只允许作用于本次运行创建或明确登记的测试对象。
- 清理失败不得覆盖主测试结果，必须单独记录状态和人工处理清单。

验收标准：

- 新增智能体、环境资产、想定、运行和删除形成可重复闭环。
- 场景结束后无未登记残留；清理成功率进入报告和基准统计。
- 中途取消、浏览器崩溃和服务异常后仍能列出待清理对象。

### GAE-GUI-07：项目级业务上下文包

当前问题：装备智能体、模型实例、想定、DoE、参与方、OODA、仿真运行和评估结果具有特定业务关系，通用模型不能仅凭页面文本稳定理解。

更新范围：

- 项目配置增加版本化业务上下文包：术语、对象、状态、关系、允许／禁止动作、示例目标和清理规则。
- Planner 每次决策读取不可变目标、上下文版本和最新脱敏 Observation。
- 信息不足或业务语义冲突时请求澄清，不猜测专业含义。
- 报告记录使用的上下文版本和影响决策的规则。

验收标准：

- Agent 能区分模型、实例、想定、DoE 和运行记录，不跨对象误操作。
- 同一业务目标在固定上下文和数据下重复 5 次，分解路径语义一致。
- 上下文更新前后可在同一基准集对比。

### GAE-GUI-08：副作用策略矩阵

当前问题：上传、复制、创建、启动、停止、删除、退出登录等动作不能只依靠指导书文字约束。

更新范围：

- 项目级配置每类动作：自动允许、需要确认、永久禁止、仅 cleanup 允许。
- 动作规则可绑定对象范围、租户、环境和测试数据前缀。
- 计划审核和运行前均校验；运行中的动态 Agent 动作使用同一策略。
- 人工确认显示对象、影响、当前状态、预期后果和清理方案。

验收标准：

- 未授权租户中的创建、启动、上传和删除均被阻断。
- 专用测试租户可按矩阵逐项确认，并保留一次性审计。
- 规则更新后旧计划回放不能绕过新策略。

## 4. P1 更新需求

### GAE-GUI-09：复杂 Web 组件适配

- 支持非原生下拉框、listbox／option、日期时间范围、分页、树、级联选择和弹窗焦点管理。
- 原生 `select_option` 失败时不得静默改为坐标点击；应进入结构化组件策略或明确 fallback。
- 验收覆盖创建人、参与方、状态、排序、想定、DoE、开始／结束时间和分页筛选。

### GAE-GUI-10：通用视觉手势

- 在 Playwright Executor 内增加拖拽、按下／移动／释放、连续点选、矩形框选、滚轮缩放和 Canvas 相对坐标序列。
- 每个视觉动作记录触发原因、坐标来源、Canvas 边界、置信度及动作前后状态。
- 低置信度或场景无变化时停止，不连续猜测。

### GAE-GUI-11：Cesium Adapter／App Bridge

- 定义通用 Bridge 接口及 Cesium 适配层，至少覆盖场景就绪、实体、图层、相机、选中对象、路径、POI、围栏和仿真时钟。
- Bridge 只提供语义状态和屏幕位置，实际浏览器动作仍由 Playwright 执行。
- 被测系统不提供 Bridge 时仍保留 L0／L1 视觉路径，并明确稳定性降级。

### GAE-GUI-12：Canvas／Cesium 断言与问题检测

- 支持实体存在／选中、图层切换、相机范围、路径点、围栏、时钟状态和瓦片加载完成断言。
- 检测 WebGL／瓦片／资源失败、场景空白、对象不可见、点击无状态变化和坐标漂移。
- 事实和推断分离，Canvas 问题必须附场景状态或像素证据。

### GAE-GUI-13：认证与角色矩阵

- 覆盖租户登录、登录失败、登录态过期、权限不足、退出确认和不同角色数据范围。
- 微信登录在没有安全自动化方案前明确标记人工步骤，不伪造自动化成功。
- storageState、Cookie 和账号信息继续加密存储并按域名限制。

### GAE-GUI-14：企业基准执行与统计

- 建立至少 30 个固定场景，覆盖登录、导航、筛选、弹窗、文件、业务闭环、异步运行和 Cesium。
- 同版本固定数据重复运行 5 次。
- 统计完成率、稳定回放率、证据完整率、清理成功率、人工确认率、视觉 fallback 率、执行模式和 A～D 等级。

验收门槛需由企业负责人确认，未确认前不得自行降低标准或宣称通过。

## 5. 依赖目标系统补充的资料

以下内容不能由 AI-GUI 单方面猜测：

1. 专用测试租户、角色权限、允许执行的副作用动作和测试时间窗。
2. 固定智能体／想定／DoE／运行数据，以及可安全删除的数据前缀。
3. 合法和非法 JSON、ZIP、HGT、图片测试文件及预期结果。
4. 仿真／训练状态机、最长正常耗时、失败状态和恢复规则。
5. 下载文件格式、关键字段、命名和完整性标准。
6. Cesium 图层、实体、相机、路径、围栏、时钟等业务断言，以及能否提供 App Bridge。
7. 脱敏兼容性扫描、关键 DOM／ARIA、Console、HTTP／WebSocket 和页面截图证据。
8. 清理失败时的人工联系人、回滚方式和数据保留要求。

## 6. `1.30.10` 未来实施顺序

以下顺序只在 `1.30.00` 满足企业负责人原始需求并完成验收、按版本复制规则建立 `1.30.10` 后生效；当前 `1.30.00` 不按此顺序开发。

1. 第一批 P0：`GAE-GUI-01` placeholder 与 `GAE-GUI-02` 作用域定位，建立登录和五个主模块导航基线。
2. 第二批 P0：`GAE-GUI-03` 上传、`GAE-GUI-04` 下载、`GAE-GUI-05` 异步状态等待。
3. 第三批 P0：`GAE-GUI-06` 数据生命周期、`GAE-GUI-07` 业务上下文包、`GAE-GUI-08` 副作用矩阵。
4. 第四批 P1：复杂组件、通用视觉手势、Cesium Adapter 和 Canvas 断言。
5. 最终基准：30 个固定场景 × 5 次重复，并使用企业内网目标系统的脱敏证据验收。

`1.30.10` 的网站适配会使用 `1.30.00` 已完成的 FR-04／FR-09 通用能力，并按上述顺序补目标站适配；不得把 `1.30.10` 的专用需求提前混入 `1.30.00`，也不得用一次视觉点击冒充完整目标网站适配。

## 7. 发布边界

- 本文是新增产品需求输入，不代表这些能力已经完成。
- GAEALaViC 指导书修订后，应逐项校准需求和验收标准，但不能以现有 GUI 限制反向缩减目标网站测试范围。
- 企业内网最终验收必须由有权限的成员在指定环境执行并回传脱敏证据。
- `1.30.00` 的企业负责人原始需求和 Definition of Done 全部通过前，不得建立或实施第一个正式网站适配版本 `1.30.10`。
- 建立 `1.30.10` 时必须遵守版本规则：新建目标版本容器、完整复制已验收的 `1.30.00`、核对文件数和字节数、冻结 `1.30.00`，之后只在 `1.30.10` 内适配 GAEALaViC。
