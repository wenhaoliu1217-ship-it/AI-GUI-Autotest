# 企业验收指南

## 环境和验收边界

本包用于 Windows x64；需要企业预置 Docker Desktop 和可正常工作的 Linux Engine。测试网站必须能被电脑和 Docker 容器访问。企业提供授权账号、测试数据、允许域名、预期结果以及模型服务配置；这些内容未从开发机复制。

本地示例验证安装与执行链，不替代企业真实网站的业务验收。模型和真实站点需要网络，离线包只免除运行依赖下载。

## 建议验收顺序

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 文件完整性 | 双击校验企业验收包.bat | 全部清单文件 SHA-256 与大小一致 |
| 启动与版本 | 双击启动入口，查看 /api/health | appVersion=1.40.01，contractCompatible=true，runnerAvailable=true，runnerMode=container |
| 基础执行 | 运行验收示例.ps1 | 真实容器浏览器执行导航、填写、点击和断言，保存报告、截图和 Trace |
| 模型连接 | 在 AI 设置中填写企业模型并运行探针 | 显示真实连接结果；无凭据时不冒充已连接 |
| 项目接入 | 创建授权测试项目并设置域名、环境 | 配置可保存；禁止访问未授权范围 |
| 网站扫描 | 在授权站点执行扫描 | 返回真实页面结构、建议及不支持范围 |
| Agent 验收 | 输入约定目标并授权当前站点的模型数据 | 观察、动作、证据及最终断言支持结论 |
| 人工接管 | 在测试站登录或触发确认 | 可等待、继续和取消，不伪造登录完成 |
| 结果与报告 | 查看本次运行详情并下载报告 | 步骤、结论、截图和 Trace 对应同一运行 |
| 关闭清理 | 正常关闭窗口，再试异常关闭后的关闭入口 | 本包端口释放；其他包和普通程序不被结束 |
| 两包并行 | 解压到两个新目录分别启动 | 端口自动避让；关闭一个不影响另一个 |

企业业务用例表请另行约定：目标、步骤或自然语言要求、输入数据、预期结果、允许的副作用、清理要求和证据位置。未测场景标为未验证，失败项记录实际原因。

## 问题定位

- 校验失败：重新下载完整 ZIP 并在新目录解压，不通过修改校验清单跳过检查。
- Docker 不可用：先解决 Docker Desktop 自身启动问题；网页可显示不等于 Runner 可执行。
- 网站不可达：检查企业 VPN、防火墙、域名及容器内访问；私网访问需要项目明确授权。
- 模型不可用：检查企业 API 地址、密钥、模型名称及权限，重新运行探针。
- 登录失败：由企业授权人员完成登录，不把密码或 Cookie 发到公共仓库。
- 证据与日志：本次证据在 artifacts，本次启动日志在 server-stdout.log 和 server-stderr.log；对外分享前按企业要求处理敏感内容。

## 运行时清单校正

原分享包的 TAR 文件 SHA-256 与原清单一致，但其中记录的镜像 ID 与 TAR 实际配置摘要不一致。本交付包未修改镜像层和配置，使用 TAR 配置的实际 SHA-256 作为镜像 ID，并保留原记录用于追溯。镜像只另设 1.40.01 标签，避免覆盖其他版本。启动器仍严格校验该实际 ID。
