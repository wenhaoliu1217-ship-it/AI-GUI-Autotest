# 内网参数化快速通道

## 目标

固定目标站点为 `http://192.168.31.218:7991`。在不修改目标站点源码、继续使用当前外部模型网关的前提下，优先用当前页面的结构化语义完成高置信动作，降低截图识别等待和点错对象的概率。

## 本次实现

1. 自然语言任务先编译为运行时参数：对象类型、对象名、动作集合、创建意图和删除意图。对象名来自本次目标或本次 `testData`，不存在 `test_D` 白名单，也不按名称生成脚本。
2. 想定/模型列表支持确定性导航、搜索与卡片内操作：先使用当前观察生成的短期 `runtimeId` 搜索，再用“精确对象名 + 卡片作用域 + 修改按钮”定位，避免在其他卡片的无名图标按钮上误点。
3. 已精确绑定想定后，具备唯一语义按钮和合法状态时可直接启动；停止动作只有在所需运行证据满足后才会发出，避免提前结束仿真。
4. 快速通道结果记为 `protocol=local`，不上传截图、不调用外部模型、不消耗模型调用预算或 token。证据事件使用 `local_decision`，便于与 `model_decision` 分开统计。
5. 任何不明确、非唯一、语义缺失或三维画布动作都自动退回当前外部模型网关。网关仍是通用与视觉操作的最终后备。
6. 删除意图永远不进入快速通道。现有执行确认层会在实际删除按钮动作前逐次要求人工批准；否定语句（如“禁止删除”）不会误触发确认。

## 安全边界

- 自动范围：创建、修改、保存、启动、停止，以及为这些动作进行的导航、搜索和打开。
- 删除：必须逐次人工批准，不能由经验回放或本地快速通道自动执行。
- 快速通道只在当前观察中目标唯一时行动；条件不满足就回退，不猜测坐标。
- 当前指令优先于界面可能残留的旧 `testData`，防止上一任务的名称串入本次执行。

## 当前覆盖与后续扩展

当前快速覆盖的是最常见且最容易点错的“进入列表 → 搜索动态名称 → 打开正确卡片”路径、普通原生表单，以及精确绑定后的启动/停止。复杂下拉/级联组件、文件上传、验证码、密钥字段和三维画布仍由外部模型处理。

后续应按“页面状态能力”扩展，而不是按测试名称扩展：

- 为复杂下拉、级联选择器等稳定组件增加结构化适配器；
- 为修改/保存增加字段级前后值证据和保存后重开校验；
- 对三维画布接入站点桥接或可验证的场景对象 API，视觉模型只处理无法结构化的空间决策；
- 将前端运行详情改为增量事件接口，避免每 800ms 拉取大型完整运行 JSON；
- 增加超时分层和熔断：本地路由毫秒级，DOM 动作秒级，模型只在必要时调用，并限制单次网关重试总时长。

- 后端非浏览器完整回归：385 项通过。
- 第一阶段执行环境曾因 `EPERM` 无法启动 3 项 Playwright 浏览器测试；第三阶段已在当前环境重新执行并全部通过。
- 2026-09-05 在线检查时目标站点返回 `ERR_EMPTY_RESPONSE`，因此尚未完成真实内网端到端验收。

## 第二阶段离线更新

- 新增 `/api/runs/{run_id}/progress` 增量进度接口。前端携带步骤、模型调用和确认记录游标，后端只返回游标之后的新记录，避免每 800ms 重传完整观察、截图元数据和历史步骤。
- 活动运行在前端本地合并增量；状态进入终态后只额外获取一次完整运行详情，保证报告、问题和最终断言完整。
- 增量客户端兼容旧接口：若后端仍返回完整运行对象，会自动使用原有解析路径。
- 逐步结构化模型请求仍使用当前外部网关，但单次请求上限由 45 秒收紧为 30 秒；连接阶段最多等待 10 秒。原有 JSON Schema 兼容回退、断路器、运行恢复检查点和新截图重决策均保留。
- 已重新生成 `frontend-dist`，一键启动包会直接使用本次增量轮询实现。
- 第二阶段后端非浏览器回归 388 项通过，前端 TypeScript 检查与生产构建通过。前端既有 Vitest 基线仍为 12 项通过、10 项失败，失败集中在旧 UI 文案和重复按钮选择器，与本次增量协议无关。

## 第三阶段离线更新

- 新增通用参数化表单执行器，不按 `test_D` 或任何固定资源名生成脚本。运行时从当前自然语言目标和 `testData` 取得名称、描述、备注、路径名、速度、时长等字段值，再按当前页面的唯一结构化控件逐项填写。
- 表单快速通道仅操作普通且唯一的 `textbox`/`spinbutton`，优先使用当前观察生成的 `runtimeId`。搜索框、密码/令牌/凭据字段、上传、验证码、下拉/级联自定义组件均拒绝本地猜测并回退外部模型。
- 只有本次运行确有成功字段填写、必填项不存在空值/无效状态、提交按钮唯一，并且创建任务获得本次明确授权时，才会发出保存或创建动作。删除任务不会由该执行器产生任何动作，仍必须逐次人工批准。
- 想定与模型列表现在会从通用卡片标题、卡片头和 `data-resource-name` 采集任意资源名称，不再只识别 `test_*`。名称采集限定在对应列表路由、过滤操作按钮文案并限制长度；创建后的验收仍要求列表中精确出现本次名称。
- 以“九月红蓝对抗想定-临时09”为例，已验证“自然语言/测试数据参数 → 表单填写 → 创建证据 → 列表精确名称验收”链路，不需要新增同名脚本。
- 第三阶段相关定向回归 121 项通过；后端完整回归 400 项通过、2 项既有警告，其中 3 项真实启动本地 Chromium 的 Playwright 测试也已单独通过。真实站点仍需接入公司内网后完成一次端到端验收。
