# 模型服务暂时不可用时的恢复行为

模型决策恢复同时处理临时超时、连接失败、429/5xx，以及经过一次有界修复后仍不符合本地契约的模型输出。上述失败不会被误判成页面控件错误或目标网站业务缺陷。

## 运行行为

1. Agent 已经完成的浏览器动作不会重放。
2. 临时服务失败后，Runner 保持运行状态，写入脱敏检查点，并按 `2s、5s、10s` 退避；输出契约错误不做无意义等待，但走相同的重新观察流程。
3. 每次退避结束都会重新截图、重新读取当前页面语义信息，再向模型请求新的决策。
4. 连续失败最多恢复 3 次；一次成功模型决策会清零连续失败数，总恢复次数仍单独保留且检查点文件名不会覆盖。
5. 失败的模型调用也消耗 `maxModelCalls` 预算；成功调用记录与尝试次数分别统计。
6. 401/403/404、无效模型等配置错误不重试；缺少当前截图等本地契约错误也不重试。
7. 最终未完成时，报告会区分 `model_service_unavailable`、`model_configuration_error`、`model_output_recovery_exhausted`、`model_local_contract_error`、`time_limit_exceeded` 和 `model_recovery_recapture_failed`，并明确它们不证明网站存在 Bug。

## 检查点

检查点位于运行产物的 `checkpoints/model-recovery-N.json`，只保存运行编号、已执行步骤数、当前 URL（脱敏）、页面状态键、截图路径和恢复计数。检查点明确写入 `automaticActionReplayAllowed=false`，不保存 Cookie、API Key、密码、动作载荷或表单值。

## 模型请求参数

普通模型请求最多尝试 2 次，单次请求超时为 45 秒。兼容 Responses 网关明确返回 `invalid_json_schema` 等机器码时，只移除网关侧 Schema 包装，响应仍必须经过本地 Schema/Pydantic 校验；该端点与模型组合会在当前进程中记忆此能力，后续页面决策不再重复触发同一个 400。
