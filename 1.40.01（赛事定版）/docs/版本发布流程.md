# 版本发布流程

## 唯一修改位置

所有 Python、测试、适配器和运行逻辑只允许修改本目录的 `backend/`。
桌面上的 `1.32.01`、`1.32.02` 等目录只用于运行和验收，禁止直接编辑。

前端目前只有 `frontend-dist/` 编译产物。没有恢复前端源码之前，不得把
压缩 JS 的字符串替换当作正常开发流程。

## 每次发布

1. 在本目录修改代码并运行测试。
2. 更新 `VERSION`，版本号必须唯一递增。
3. 使用 `New-Release.ps1` 指定一个全新的输出目录。
4. 使用 `Verify-Release.ps1` 校验发布包内部文件哈希。
5. 在干净环境启动新目录，确认 `/api/health` 的版本和路径正确。
6. 只有真实网站回归和证据检查完成后，才把该目录交付使用。

发布脚本不会覆盖旧目录，也不会复制旧的 `data`、`artifacts` 或 PID 文件。

## 运行时边界

Python 运行时和 Docker Runner 镜像属于发布依赖，不属于源码提交。每个
发布包必须保留 `runtime/runtime-manifest.json`，并在报告中记录镜像 ID、
Python 版本和 Playwright 版本。
