## 一、用户是谁，以及产品必须怎么做

用户是完全不会编程的产品负责人，依靠 AI 开发和验收本项目。所有界面文案、流程和错误提示都必须让完全不懂技术的人看懂。

产品定位已经明确：

1. 只做 Web 端。旧的“小程序、Windows 等多端五周路线”不再属于当前需求。
2. 普通用户的主流程必须是：输入一个网站地址 → AI 扫描网站 → 在聊天框里用普通中文说想测试什么 → 确认 → 看到 AI 实时操作网站 → 得到普通中文结果。
3. 普通模式不显示“项目、环境、场景”三个技术层级。这些信息可以在系统内部继续保存。
4. 普通用户不需要理解测试脚本、选择器、JSON、Token、Playwright、Runner、Agent 等词。出现这些词时必须换成直白中文。
5. GUI 工作台应当左侧显示网站实时画面，右侧显示 AI 聊天、当前动作、审批和结果。
6. 重点实测京东、`https://ion.cesium.com`、GAEALaViC，同时必须支持用户填写其他任意合法网站，不能把逻辑写死为三个站点。
7. 不能在普通页面把三个重点站点做成卡片。用户可能不认识这些网站，而且 Cesium 和 GAEALaViC 的能力有重叠。它们只能作为内部适配和验收对象。
8. 京东仍保留全部 65 个闭环业务场景，但普通用户不能看到 `J01～J65` 编号。界面只用业务语言表达。
9. 电商完整流程允许创建未支付订单，但本项目验收绝不实际付款。产品支持到付款环节由用户本人接管；输密码、指纹、刷脸及实际付款必须由用户完成。本项目验收必须在付款前停止。
10. 删除账号、修改密码、付款、泄露密钥等绝对危险动作永远不能自动绕过安全规则。

## 三、三档审批规则

聊天框下方需要提供类似 Codex 的三档模式：

1. `请求批准`：所有会写入网站的动作，每次都让用户确认。
2. `替我审批`：同类低风险动作可以自动确认，高风险动作每次确认。
3. `完全访问权限`：允许范围内的动作自动确认，聊天框上方持续显示醒目警告；绝对禁止动作仍然拦截。

写字、勾选、选择、上传、加入购物车等是“操作确认”或“高风险动作确认”，不能把所有普通填写都吓人地称为“危险动作”。验证码、二维码、风控、人脸、支付认证等必须让用户本人接管。

## 四、登录流程规则

正确流程是：

1. AI 判断当前任务确实需要登录；或用户主动点击“登录账号后再测试”。
2. 在用户启动 GUI 的同一个 Microsoft Edge 窗口中新增网站标签页。
3. 用户本人正常登录，GUI 不读取、不保存密码。
4. 用户回到 GUI 点击“我已登录”。
5. 系统重新扫描登录后的页面并继续，不能反复要求登录。

注意：普通公开网页只出现“登录”入口，不等于必须登录。只有页面被登录墙拦截、当前任务明确需要账号功能，或用户主动要求登录时，才进入登录流程。

登录窗口不能依赖 Chrome，也不能另起一个网络环境不同的孤立内置浏览器。现在的实现优先使用 Windows 自带 Edge，同一窗口新增标签页。

### 当前仍存在的核心产品故障：单项失败会切断整轮对话

这个问题尚未修复：

1. 当前普通聊天任务仍是一次性的单个 Agent Run。
2. 一个步骤失败后，后端会结束本次 Run，后续场景不会自动继续。
3. 前端只对有限的结束状态显示恢复输入框；其他包装状态或异常状态仍可能让输入框消失。
4. 即使恢复输入框出现，按钮目前仍是“重新开始测试”，实际会创建全新的 Run，没有把上一轮步骤、失败原因和用户的新消息作为同一对话上下文继续交给 AI。
5. 因此用户不能可靠发送“跳过失败项继续下一项”“换一种方式重试”“把本项记为失败并完成剩余场景”等消息。
6. 内部批次页虽然有“继续”和“重试失败项”，普通小白聊天流程并没有接通这些能力，不能据此宣称问题已解决。

正确目标：

- 单项失败只记录该场景失败，默认继续下一个安全且独立的场景。
- 只有登录失效、网站整体不可达、AI 服务不可用或用户主动终止等全局阻塞，才暂停整批。
- 右侧聊天框在运行中、人工接管、单项失败、批次暂停和批次结束后都保持可用。
- 用户可以发送“继续、跳过、重试这一项、修改后续要求、停止整个测试”。
- AI 必须说明刚才哪项失败、是否已记录、接下来准备做什么。
- 后端保留同一测试会话的消息历史、已完成项、失败项、剩余项和当前页面状态，不能只新建一个没有上下文的 Run。
- 京东 65 项和 Cesium 最终确认数量的任务应作为可续跑批次，单项失败不能终止整批。

### 17.6 Windows 启动时误开京东旧标签页的修复

1. 原因已确认：`双击启动AI测试.bat` 没有写死京东网址；专用 Edge 配置为了复用网站登录状态，会保存之前测试留下的标签页会话。旧逻辑只在启动 2 秒后清理一次，可能漏掉稍晚恢复的京东标签页。
2. 已修改唯一对应启动器 `Windows一键运行\start.ps1`：启动 Edge 前只删除专用配置中的 `Default\Sessions` 标签页会话文件，不删除 Cookie、Local Storage 或其他登录状态。
3. 启动 Edge 后由一次性清理改为连续检查 8 秒；识别到 GUI 标签页后只保留一个 GUI 页面，关闭迟到恢复的旧网站页、欢迎页和重复页。
4. 清理结果写入 `Windows一键运行\browser-cleanup.log`，日志不记录被关闭页面的完整网址，避免查询参数或敏感信息进入证据。
5. PowerShell 语法解析和关键行为断言已经通过。当前用户会话没有开放浏览器控制端口，为避免打断已登录状态，本轮没有强制重启；下次双击启动时需做一次可见复验，验收标准是只打开 GUI、网站登录状态仍可复用、不会额外出现京东旧页面。
6. 此项属于 Windows 封装启动逻辑，源码目录没有对应的第二份 `start.ps1`；没有修改 Cesium/JD 任务执行功能，也没有重建 Runner、TAR 或最终 ZIP。
