# AI-GUI 最终能力标准指导书：面向京东电商完整接入测试

文档状态：最终目标标准草案  
生成日期：2026-07-21  
适用对象：AI-GUI 后续所有版本  
目标系统：京东消费者 Web 站、官方帮助体系及经授权的隔离交易环境  
原则：只定义最终要实现的电商测试能力，不描述任何阶段性 GUI 版本现状。

## 1. 文档定位

本文档定义 AI-GUI 为完整测试京东型综合电商平台必须达到的最终能力标准。京东作为第三类验证目标，用于检验 AI-GUI 是否能从仿真/GIS 平台扩展到高动态、高副作用、高资金风险的交易系统。

本文档回答四个问题：

1. 京东消费者电商网站包含什么业务、页面、控件和状态。
2. 商品、购物车、优惠、库存、支付、订单和退款应怎样形成真实闭环。
3. AI-GUI 为稳定跑通这些流程必须具备什么通用能力。
4. 什么数据、证据、清理结果和指标才算验收通过。

禁止以下伪验收：

- 搜索页能打开就算搜索正确。
- 看到价格就算价格计算正确。
- 点击加入购物车就算购物车正确。
- 进入收银台就算支付成功。
- 页面出现订单号就算库存、优惠和支付都正确。
- 点击退款按钮就算退款到账。
- 在正式站真实扣款或真实发货来证明自动化能力。
- 只生成测试计划，没有执行和业务状态证据。

## 2. 测试环境分层与安全边界

京东正式消费者站不是公开的自动化交易沙箱。完整测试必须分两层执行。

### 2.1 正式站只读与低副作用层

允许验证：

- 登录态、首页、类目、搜索、筛选、排序和分页。
- 商品详情、公开价格、促销展示、服务承诺、评价和帮助信息。
- 空购物车、账户中心、订单/优惠券/售后/发票页面结构。
- 在专用账号且明确授权时，验证可回滚的收藏、关注或购物车动作。

默认禁止：

- 提交真实订单。
- 真实支付、白条、分期、礼品卡或余额扣款。
- 写入真实地址、手机号、身份证或发票抬头。
- 领取消耗型优惠券、申请价格保护、确认收货、评价或售后。
- 联系真实商家/客服、发送消息或触发真实短信。

### 2.2 隔离交易闭环层

以下业务必须在京东授权测试环境、企业内部仿真环境或等价的受控电商沙箱中执行：

- 固定商品和 SKU。
- 固定库存及库存查询接口。
- 固定价格、促销、优惠券和运费规则。
- 测试收货地址、虚拟物流和测试发票。
- 支付沙箱、模拟银行/白条结果和签名验证。
- 订单取消、退款、退货、换货和逆向物流。
- 可查询的订单、库存、支付和退款后台状态。
- 一键清理或重置测试数据。

无法取得隔离交易环境时，可以完成页面和只读业务盘点，但不能宣称支付、库存、退款完整闭环已经通过。

## 3. 事实依据与已确认页面

2026-07-21 使用登录后的专用会话进行只读检查，没有记录账号、手机号、地址、订单号、支付信息或其他个人数据。

已确认页面：

| 页面 | 主要功能 |
|---|---|
| 首页 | 搜索、类目、频道、秒杀、补贴、推荐、领券和帮助入口 |
| 搜索结果 | 搜索词、购物灵感、模式切换、筛选、排序、分页和商品卡片 |
| 商品详情 | SKU、价格、优惠、配送、服务、数量、购物车、立即购买、评价和售后 |
| 购物车 | 空态、配送区域、商品行、合计和结算入口 |
| 我的京东 | 订单、足迹、收藏、店铺关注、优惠券、京豆、礼品卡和白条入口 |
| 我的订单 | 全部订单、待付款、待评价、回收站、时间筛选、订单状态和操作 |
| 优惠券 | 可用、已用、过期、回收站、兑换和规则说明 |
| 售后 | 申请售后、记录、维修、退款说明和服务承诺 |
| 发票 | 发票列表、订单详情、类型、状态、操作和补开发票 |

已确认的消费者站官方帮助入口包括购物流程、配送方式、在线支付、分期付款、公司转账、售后政策、退款说明、返修/退换货和取消订单。

## 4. 电商业务全景

### 4.1 核心闭环

```text
登录或建立游客会话
-> 选择配送地区
-> 搜索/浏览商品
-> 筛选并定位目标 SPU/SKU
-> 查看价格、库存、促销和履约承诺
-> 选择规格、服务和数量
-> 加入购物车
-> 修改购物车并选择优惠
-> 进入结算
-> 选择地址、配送、发票和支付方式
-> 校验最终应付金额和库存锁定
-> 提交订单并取得 orderId
-> 支付沙箱回调
-> 订单进入待发货/履约状态
-> 模拟发货、物流和收货
-> 完成订单或申请取消/售后
-> 退款到账并释放库存/优惠权益
-> 清理测试数据并生成报告
```

### 4.2 业务对象关系

```text
用户 / 会员 / 企业账号
  -> 登录态 / 风控状态 / 权益
  -> 地址 / 发票抬头 / 支付方式
  -> 收藏 / 关注 / 足迹
  -> 优惠券 / 京豆 / 礼品卡 / 会员权益

类目 / 店铺 / 品牌
  -> SPU
      -> SKU
          -> 地区库存
          -> 基础价 / 到手价 / 促销价
          -> 服务 / 保障 / 配送承诺

SKU
  -> 购物车行
      -> 选中状态 / 数量 / 赠品 / 换购 / 优惠分摊
      -> 结算单
          -> 地址 / 配送 / 运费 / 税费 / 发票 / 优惠
          -> 订单
              -> 支付单
              -> 库存锁定
              -> 履约单 / 物流
              -> 售后单 / 退款单 / 逆向物流
```

### 4.3 角色矩阵

| 角色 | 主要能力 | 测试用途 |
|---|---|---|
| 游客 | 浏览、搜索、查看商品 | 认证边界与游客体验 |
| 专用买家 | 购物车、结算、订单、售后 | 消费者闭环 |
| PLUS/会员测试账号 | 会员价、权益、运费规则 | 权益差异 |
| 企业购测试账号 | 企业商品、对公支付、企业发票 | B2B 分支 |
| 商家测试账号 | 商品、价格、库存、发货、售后审核 | 供给与履约闭环 |
| 客服/售后账号 | 取消、退款、退换货审核 | 逆向流程 |
| 运营/管理员 | 促销、券、风控、审计 | 平台规则验证 |

没有对应后台账号时，不得通过消费者页面猜测后台状态；应使用经授权的只读测试 API 或明确记录为环境前置条件。

## 5. 关键状态机

### 5.1 商品与库存

```text
草稿/待审核 -> 上架 -> 可售
可售 -> 库存不足/售罄/下架
订单提交 -> 预占/锁定库存
支付失败或取消 -> 释放库存
支付成功 -> 扣减/确认库存
退款退货 -> 按业务规则恢复或不恢复库存
```

测试断言必须按 `skuId + regionId + warehouseId` 或测试环境实际库存键验证，不能只看“有货”文字。

### 5.2 购物车

```text
不存在 -> 加入 -> 未选中/选中
-> 修改数量/规格/服务
-> 应用促销/优惠
-> 移入关注/删除/失效
-> 进入结算
```

### 5.3 订单

不同业务线的页面文案可以不同，但必须映射到统一状态：

```text
待提交
-> 待付款
-> 已付款/待发货
-> 已发货/待收货
-> 已收货/待评价
-> 已完成

待付款 -> 已取消/超时关闭
已付款 -> 取消审核/退款中 -> 已取消/已退款
任一可售后状态 -> 售后申请中 -> 处理中 -> 完成/驳回/关闭
```

### 5.4 支付与退款

```text
支付单创建
-> 待支付
-> 支付成功 / 支付失败 / 用户取消 / 超时

支付成功回调
-> 验签
-> 幂等处理
-> 订单状态更新

退款申请
-> 审核/自动批准
-> 退款处理中
-> 退款成功/失败
-> 原路退回或明确的替代去向
```

重复支付回调、重复退款回调和网络重试不得产生重复扣款或重复退款。

## 6. 必须覆盖的网站模块与控件

### 6.1 登录、注册与风险验证

登录页至少包含：

- 账号名/手机号/邮箱。
- 密码。
- 手机号和验证码登录。
- 获取验证码。
- 微信登录、QQ 登录。
- 忘记密码、立即注册。
- 二维码登录及刷新。
- 隐私政策、改进建议和帮助。

必须测试：

- 正确/错误账号、空值、格式错误和连续失败。
- 密码、短信、二维码、微信/QQ 登录分支。
- 二维码过期、刷新、扫码取消和异地确认。
- 验证码、滑块、设备确认或风控出现时人工接管。
- 登录成功返回原页面，搜索条件和购物上下文按规则保留。
- 会话过期、退出和多设备会话策略。
- 所有账号、密码、验证码、cookie 和设备标识脱敏。

### 6.2 首页、类目与频道

必须覆盖：

- 搜索框、搜索按钮、联想词和历史词。
- 全部类目及多级类目。
- 秒杀、补贴、排行榜、领券、企业购、二手、生鲜、全球购等频道。
- 推荐商品、广告、直播和活动入口。
- 配送地区、网站导航、购物车、订单、我的京东、客服和无障碍入口。
- 购物、配送、支付、售后和特色服务帮助链接。

必须验证活动倒计时、频道跳转、广告标识、推荐加载、个性化与未登录差异。动态推荐商品名称和数量不得作为稳定断言。

### 6.3 搜索、筛选与排序

已确认的搜索能力包括：

- 搜索词和购物灵感。
- 商品、新品、店铺、企业采购和工业品等结果类型。
- 传统模式/简洁模式。
- 综合、销量、价格排序。
- 价格区间。
- 京东自营、京东物流、品牌、拍拍二手、京东国际、货到付款、仅显示有货、全球配送等筛选。
- 配送地区、分页、跳页和总页数。

必须测试：

- 精确词、模糊词、空词、特殊字符、中英文、长词和无结果。
- 联想词、纠错、历史词和清除。
- 筛选组合、清空筛选、筛选后页码重置。
- 价格升降序、销量和综合排序。
- 广告商品必须有广告标识，不与自然结果混淆。
- 商品卡片的 `skuId`、标题、价格、促销、自营/物流、店铺、销量和库存状态。
- 下一页、上一页、边界页和跳页。
- 搜索 URL 参数、页面状态和后端查询条件一致。

### 6.4 商品详情

页面至少覆盖：

- 面包屑、品牌、店铺、SKU 标题和商品 ID。
- 主图、视频、缩略图、放大和切换。
- 基础价、促销价、到手价、补贴和价格说明。
- 促销、优惠券、赠品、换购和会员权益。
- 颜色、版本、容量、套装等 SKU 属性。
- 配送地区、库存、预计送达、运费和自提。
- 服务承诺、价保、只换不修、延保、试用和回收。
- 白条/分期展示。
- 数量减、数量输入、数量加。
- 加入购物车、立即购买。
- 大家评、店铺、商品详情、规格参数、售后保障、推荐、商品对比、买家评价。
- 关注店铺、联系客服、搜本店、搜全站。

必须测试：

- SPU 与每个 SKU 属性组合映射到唯一 `skuId`。
- 切换 SKU 后价格、库存、图片、促销和配送同步变化。
- 地区变化后库存、运费和预计时间同步变化。
- 数量最小值、最大值、库存上限、非法输入和步进按钮。
- 服务/保障费用纳入结算但不改变商品单价。
- 页面展示价、购物车价和结算价的差异必须可解释。
- 评价数量、好评标签和分页不作为固定常量。
- 加入购物车和立即购买是写操作，执行前必须登记目标 SKU、数量和清理动作。

### 6.5 购物车

必须覆盖：

- 空购物车状态和去购物入口。
- 配送地区。
- 自营/店铺分组。
- 商品行：选择、SKU、单价、数量、小计、促销、库存和操作。
- 全选、取消全选、删除、移入关注和清空失效商品。
- 赠品、换购、加价购、套装和预售。
- 优惠券/促销选择。
- 已选择件数、合计、优惠金额、运费提示和去结算。

必须测试：

- 同一 SKU 重复加入的合并规则。
- 不同 SKU、不同店铺、跨仓和失效商品。
- 数量加减、直接输入、库存上限和并发库存变化。
- 单选、分组选择、全选和跨店优惠作用域。
- 删除取消/确认、批量删除和清理。
- 刷新、重新登录和多标签页后的购物车一致性。
- 合计金额必须以十进制定点计算，并与后端优惠明细一致。
- `去结算` 只在隔离交易环境执行。

### 6.6 结算页

必须覆盖：

- 收货人、手机号和地址。
- 新增、编辑、删除和默认地址。
- 配送方式、配送时间、自提和运费。
- 商品清单、数量、赠品和服务。
- 发票类型、抬头、税号和内容。
- 优惠券、京豆、礼品卡、红包、会员权益和促销。
- 支付方式。
- 商品金额、优惠分摊、运费、服务费、税费和应付金额。
- 提交订单、返回购物车和库存/价格变化提示。

精确断言：

```text
应付金额 = 商品金额
         - 商品级优惠
         - 店铺级优惠
         - 平台级优惠
         - 优惠券/京豆/礼品卡抵扣
         + 运费
         + 服务费
         + 税费
```

每项金额必须来自页面和订单预结算接口，使用 decimal，不允许二进制浮点误差。

### 6.7 优惠、促销和权益

已确认优惠券页面包括可用、已用、过期、回收站、兑换和规则说明。

必须测试：

- 满减、折扣、直减、品类券、店铺券、平台券、运费券。
- 可叠加、互斥、最优券、手动选券和取消选券。
- 未开始、已过期、已用、被占用、地区/品类/SKU 不适用。
- 京豆、礼品卡、会员价、企业价、补贴和首购权益。
- 优惠分摊到商品行、取消/退款后的权益返还。
- 倒计时结束时页面和结算规则一致。
- 正式站不得自动领取或消耗真实权益。

### 6.8 库存与价格变化

必须测试：

- 有货、无货、库存不足、限购、预售和区域不可售。
- 商品页有货但结算前售罄。
- 两个会话同时购买最后库存。
- 下单锁定、支付超时释放、取消释放、退款恢复规则。
- 商品基础价、实时促销价、购物车价、结算价和订单快照价。
- 下单前涨价/降价、价保入口和价保失败原因。

必须通过库存/订单测试 API 或后台状态证明锁定和释放，不能只用页面文案推断。

### 6.9 支付

正式站支付不可自动提交。隔离环境必须覆盖：

- 在线支付、货到付款、分期、公司转账及目标环境实际支持方式。
- 支付页跳转、新窗口、iframe、二维码和倒计时。
- 成功、失败、取消、超时、处理中和未知状态。
- 金额、订单号、支付单号和币种一致。
- 签名、时间戳、nonce、防重放和回调来源。
- 重复点击支付、重复回调和浏览器返回。
- 支付成功但页面超时、页面成功但后台未记账等不一致。
- 支付凭证、银行卡、身份和设备信息全链路脱敏。

### 6.10 我的京东与个人资产

已确认入口包括：

- 我的订单、待付款、待收货、待评价。
- 我的足迹、商品收藏、店铺关注。
- 优惠券、京豆、礼品卡、白条和会员入口。
- 编辑资料、价格保护和京东钱包。

必须测试列表、空态、分页、搜索、取消关注、删除足迹和权益跳转。任何个人资料、金融服务或真实资产变更都默认禁止。

### 6.11 订单中心

已确认功能包括：

- 全部订单、待付款、待评价、订单回收站。
- 近三个月、当年和历史年份筛选。
- 订单详情、金额、状态和操作。
- 取消订单、评价晒单、返修退换货和发票。

必须测试：

- 使用 `orderId` 定位订单，不依赖商品名称或列表位置。
- 时间、状态、关键字和商品筛选。
- 待付款支付/取消、已发货物流、确认收货和已完成。
- 重复提交订单不得产生多个有效订单。
- 订单详情的商品快照、价格、优惠、地址脱敏、配送、发票和支付一致。
- 删除到回收站、恢复和永久删除只允许 E2E 订单。
- 历史订单和非 E2E 订单必须不可修改。

### 6.12 配送与物流

必须测试：

- 京东物流、第三方物流、自提、预约配送和跨区域配送。
- 待出库、已出库、运输中、派送、签收、异常和拒收。
- 多包裹、拆单、合单和部分发货。
- 物流节点顺序、时间、承运商和单号脱敏。
- 配送延迟、地址异常、不可达和改约。
- 确认收货必须属于高风险确认动作。

### 6.13 售后、取消和退款

已确认功能包括申请售后、返修/退换货记录、维修明细、退货/换货、闪电退款、退款周期和售后服务承诺。

必须测试：

- 未支付取消、已支付取消和已发货拦截失败。
- 整单退款、部分商品退款、部分数量退款和运费处理。
- 退货、换货、维修、拒收和仅退款。
- 原因、说明、图片/视频凭证上传。
- 审核通过、驳回、补充资料、撤销和超时。
- 逆向物流、商家收货、质检和退款。
- 退款金额、优惠分摊、券/京豆/礼品卡返还和库存恢复。
- 重复申请和重复退款回调幂等。

### 6.14 发票

已确认页面包括发票列表、补开发票、帮助中心、订单详情、发票类型、状态和操作。

必须测试：

- 普通电子发票、企业发票和目标环境支持类型。
- 个人/企业抬头、税号、邮箱和必填校验。
- 开票申请、处理中、成功、失败、红冲和重开。
- 下载文件名、格式、金额、税额、订单号和 SHA-256。
- 发票中的个人/企业信息在报告中脱敏。

### 6.15 评价、客服与消息

必须测试：

- 待评价、已评价、追评、服务评价和晒单。
- 星级、标签、文字、图片/视频上传和匿名设置。
- 敏感词、长度、非法文件和重复评价。
- 客服入口、机器人/人工切换、会话关闭和历史记录。
- 正式站禁止自动发送评价、咨询或客服消息。

### 6.16 企业购、商家与运营后台

为证明通用电商能力，隔离环境最终还应覆盖：

- 商品/SPU/SKU 创建、审核、上架、下架。
- 价格、库存、仓库和区域配置。
- 订单接单、拆单、发货和物流。
- 售后审核、退款和工单。
- 促销活动、优惠券、会员权益和风险规则。
- 报表、对账、发票和操作审计。

这些模块没有授权账号时只能保留为最终要求，不能在正式京东商家系统中试探访问。

## 7. AI-GUI 最终必须具备的能力

### 7.1 动态页面与定位器

必须支持：

- React/Vue/微前端、懒加载、虚拟列表和动态推荐。
- 以 `skuId`、`orderId`、`cartLineId`、`paymentId`、`refundId` 为业务主键。
- 商品卡片、购物车行、订单行和售后行的作用域定位。
- role、label、testId、稳定 data 属性、href 和业务 ID 多策略定位。
- 广告卡片与自然商品区分。
- DOM 重绘后重新定位，禁止保存失效节点。

### 7.2 多窗口、iframe 与外部跳转

必须支持支付页、登录提供方、客服、帮助和商家页面的新窗口/iframe；记录来源页、目标域名、返回值和关闭行为。只允许配置白名单域名。

### 7.3 身份、风控和人工接管

必须支持密码、短信、二维码和第三方登录。遇到验证码、滑块、扫码、设备验证或风控时暂停并由用户人工完成；AI-GUI 不得绕过反机器人或账户安全机制。

人工完成后必须从当前步骤恢复，且不重复加入购物车、提交订单或支付。

### 7.4 金额计算引擎

必须使用十进制定点数，保存：

- 原价、促销价、会员价、到手价。
- 商品级、店铺级、平台级优惠。
- 券、京豆、礼品卡和其他抵扣。
- 运费、服务费、税费和应付金额。
- 每个优惠在订单行之间的分摊和舍入规则。

金额任何一分钱差异都必须能定位到具体规则，不能使用截图 OCR 作为唯一金额来源。

### 7.5 库存与并发测试

必须支持双会话/多会话并发、屏障同步和后端库存查询，验证最后库存、超卖、锁定、释放和幂等。并发测试只允许在隔离库存池执行。

### 7.6 支付沙箱和回调

必须支持：

- 受控支付驱动器。
- 签名验证和回调模拟。
- 成功、失败、取消、超时和处理中。
- 重复/乱序回调、网络重试和幂等键。
- 支付单、订单和账务状态一致性。
- 支付数据源头脱敏。

### 7.7 异步订单和最终一致性

订单、库存、支付、物流、退款和发票均需按业务 ID 轮询。每个任务定义启动超时、业务超时、无进展超时和最大重试，禁止使用固定睡眠代替状态判定。

### 7.8 文件上传与下载

必须支持评价/售后凭证图片与视频、商家商品图片、批量模板和发票下载；记录文件名、大小、MIME、SHA-256、上传响应和下载内容校验。个人信息必须在证据中遮罩。

### 7.9 隐私与密钥保护

敏感信息包括：

- 账号、手机号、邮箱、地址和身份证信息。
- 密码、短信验证码、二维码登录状态和 cookie。
- 银行卡、白条、礼品卡、支付 token 和交易凭证。
- 订单号、物流单号、发票抬头和企业税号。

这些信息不得进入模型上下文、DOM 摘要、截图、视频、Trace、Console、网络头、剪贴板或报告。业务 ID 仅保留脱敏后缀或哈希。

### 7.10 副作用策略

每个动作必须携带：

- 动作等级。
- 目标账号和业务 ID。
- 执行前状态。
- 是否需要人工确认。
- 允许执行的环境。
- 成功清理和失败回滚。

AI-GUI 必须在动作执行前判断，而不是点击后才发现产生真实交易。

### 7.11 网络与业务证据

必须把 UI 操作关联到搜索、商品、库存、价格、购物车、预结算、订单、支付、物流、售后和退款请求。证据包括脱敏请求、状态码、耗时、业务 ID、响应 schema 和错误码。

### 7.12 证据与重放

每一步至少保存：

- runId、caseId、stepId、角色和环境层级。
- 路由、标题、关键 DOM/ARIA 摘要。
- locator、备用 locator 和目标业务 ID。
- 前后截图及动态区域状态。
- Console 和关键失败请求。
- 金额明细、状态时间线和接口证据。
- 上传/下载文件 hash。
- 创建资源台账和清理结果。
- Playwright Trace、视频和可重放脚本。

## 8. 分步骤可行性评估

| 测试步骤 | 可行性 | 推荐机制 | 必要条件 |
|---|---|---|---|
| 首页、搜索、筛选、商品详情 | 高 | Playwright + skuId 定位 | 正式站只读即可 |
| 登录 | 中高 | 人工完成二维码/验证码后复用会话 | 专用账号，不绕过风控 |
| 收藏/关注/购物车 | 高 | 专用账号 + 资源台账 | 明确授权并可清理 |
| 结算页只读 | 中 | 隔离购物车和测试地址 | 不点击提交订单 |
| 优惠组合计算 | 高 | 固定规则数据 + decimal 引擎 | 需要稳定促销快照 |
| 库存锁定/释放 | 中 | 双会话 + 库存测试 API | 需要隔离库存池 |
| 下单 | 正式站禁止、沙箱高 | 订单沙箱 + 幂等键 | 测试 SKU、地址、配送 |
| 支付 | 正式站禁止、沙箱中高 | 支付模拟器 + 回调服务 | 不接触真实资金 |
| 物流 | 中高 | 虚拟物流事件 | 可推进测试订单状态 |
| 取消/退款 | 正式站禁止、沙箱中高 | 售后 API + 退款模拟 | 可核对账务与库存 |

| 商家/运营后台 | 中 | 专用后台角色 | 需要授权测试租户 |
| 并发与性能 | 中 | 隔离环境压测 | 禁止对正式京东施压 |

低可行性来自真实资金、隐私、风控或缺少授权环境，不代表最终能力可以删除。应通过沙箱、模拟器、人工确认或测试 API 解决。

## 11. 副作用控制矩阵

| 动作 | 正式站默认 | 隔离环境 | 确认 | 清理/回滚 |
|---|---|---|---|---|
| 浏览、搜索、筛选、排序 | 允许 | 允许 | 否 | 无 |
| 切换配送地区 | 允许但不保存真实地址 | 允许 | 否 | 恢复默认区域 |
| 收藏/关注 | 禁止，除非专用账号授权 | 可逆写入 | 可选 | 取消收藏/关注 |
| 加入购物车 | 禁止，除非专用账号授权 | 可逆写入 | 可选 | 删除目标行/清空 E2E 行 |
| 领券/兑换券 | 禁止 | 可逆或消耗型 | 是 | 释放/重置测试券 |
| 新增地址/发票抬头 | 禁止 | 可逆写入 | 是 | 删除测试数据 |
| 提交订单 | 禁止 | 高风险写入 | 是 | 取消 E2E 订单 |
| 支付/分期/白条/礼品卡 | 禁止 | 仅支付沙箱 | 是 | 沙箱冲正/退款 |
| 取消订单 | 禁止 | 高风险写入 | 是 | 状态重置或重建订单 |
| 确认收货 | 禁止 | 高风险写入 | 是 | 通常不可直接回滚 |
| 申请售后/退款 | 禁止 | 高风险写入 | 是 | 撤销售后或沙箱重置 |
| 评价/晒单/客服消息 | 禁止 | 可逆写入 | 是 | 删除测试内容 |
| 下载发票 | 只读但含隐私，默认禁止 | 受控下载 | 是 | 删除本地文件 |
| 商家上架/改价/改库存 | 禁止 | E2E 商品池 | 是 | 恢复快照 |
| 批量删除/真实资金/真实物流 | 禁止 | 仅专项沙箱 | 是 | 按专项方案 |

## 12. 端到端闭环验收

### 12.1 搜索到购物车闭环

```text
登录专用买家
-> 搜索固定关键词
-> 筛选并按 skuId 定位 P01
-> 详情核对价格、库存和配送
-> 加入购物车
-> 修改数量并选择商品
-> 核对小计/合计
-> 删除目标 cartLineId
-> 验证购物车恢复初始状态
```

### 12.2 优惠到支付闭环

```text
隔离环境准备固定 SKU、库存和券
-> 加入购物车并进入结算
-> 选择测试地址、配送、发票和券
-> 核对每一项金额和分摊
-> 提交一次订单并取得 orderId
-> 支付沙箱成功回调
-> 验证支付单、订单、库存和权益一致
```

### 12.3 支付失败与库存释放闭环

```text
提交订单并锁定库存
-> 模拟支付失败/超时
-> 验证订单关闭或可重试
-> 验证库存释放
-> 验证券/京豆/礼品卡按规则返还
-> 验证重复回调无副作用
```

### 12.4 履约与完成闭环

```text
已支付订单
-> 商家/仓库确认
-> 虚拟发货
-> 物流节点推进
-> 确认收货
-> 订单完成
-> 发票生成和下载校验
```

### 12.5 售后退款闭环

```text
创建可售后 E2E 订单
-> 申请部分/整单售后
-> 上传固定凭证
-> 审核通过
-> 推进逆向物流/仅退款
-> 退款成功
-> 核对原路退回、优惠返还和库存规则
-> 清理售后、订单和测试数据
```

## 13. 非功能与异常标准

### 13.1 性能

- 首页、搜索、商品详情、购物车和订单中心分别建立性能基线。
- 记录首屏、可交互、搜索响应、加购、预结算和订单提交 p50/p95。
- 不对京东正式站做并发压测；性能/并发只在授权环境执行。

### 13.2 稳定性

- 每个固定场景连续执行 5 次。
- 重试不得重复加购、下单、支付或退款。
- 覆盖刷新、返回、多标签页、断网、会话过期和浏览器重启。

### 13.3 兼容性与可访问性

- 覆盖目标支持的 Chromium 及至少一个不同内核浏览器。
- 覆盖常用桌面视口、缩放和最小支持宽度。
- 键盘导航、焦点、表单 label、对话框和无障碍入口可用。
- 动态价格和优惠不能只依赖颜色表达。

### 13.4 安全

- 权限不足必须由服务端拒绝，不仅隐藏按钮。
- 验证订单越权、IDOR、优惠券越权和地址隔离。
- 验证重复提交、防重放、签名和幂等。
- 上传文件验证类型、大小、内容和路径安全。
- 明文账号、地址、订单和支付信息泄漏为 0。

## 15. 目标环境可观测性要求

隔离交易环境宜提供：

- 稳定的 `data-testid` 和业务 ID 属性。
- 商品、价格、库存和促销规则快照 API。
- 购物车、预结算和订单明细只读 API。
- 支付、退款和物流事件模拟器。
- 幂等键、request ID 和完整审计日志。
- 测试时钟，用于促销过期和支付超时。
- 可按 runId 查询并清理全部 E2E 资源。
- PII 脱敏的测试数据视图。

缺少这些能力时，AI-GUI 仍可执行页面测试，但库存、资金和退款等内部状态无法只凭 UI 达到高置信度验收。

## 18. 最终定义

AI-GUI 完整跑通京东型电商平台，不是指能够浏览商品或点击购买按钮，而是能够在严格安全边界内证明：目标 SKU 被正确发现，价格与优惠精确到分，购物车和结算一致，库存正确锁定和释放，支付与订单幂等，物流与售后状态可追踪，退款、权益和库存最终一致，全部证据脱敏，所有 E2E 副作用均被清理。

只有在隔离交易环境完成搜索、商品、购物车、优惠、库存、支付、订单、履约、退款和清理的完整闭环后，才能宣称 AI-GUI 已具备综合电商平台的完整测试能力。
