# 1.30.31 京东专用改动边界与迭代规则

## 版本定位

`1.30.31` 从冻结的 `1.30.30` 完整复制建立，是京东真实站问题修复增量版。它继续用于京东消费者站只读／低副作用验证和授权隔离交易环境闭环，不继承 GAEALaViC 分支，也不能成为其他网站未经筛选的母版。

## 两层环境边界

- `production_readonly`：正式消费者站只允许浏览、搜索、筛选、排序、分页、商品详情、公开价格／促销／帮助和账号页面结构。默认禁止产生交易、资金、权益、个人资料、评价、消息、售后或后台副作用。
- `isolated_transaction`：仅授权测试租户、固定 E2E 商品／库存／优惠／地址、支付沙箱和虚拟物流。每个写动作必须有人工作用域确认、幂等键、业务 ID、前后状态、资源台账和清理。

正式站写操作没有书面授权时不得执行；即使授权收藏／关注／购物车，也必须限定专用账号和可清理的目标资源。正式站永远不得自动提交真实订单、支付或售后。

## 通用能力与京东专用内容

通用候选：Decimal 金额与分摊、业务主键作用域定位、交易状态机、最终一致性等待、多会话屏障、人工接管恢复、资源台账、幂等、文件哈希、PII 脱敏和副作用策略。

京东专用：`benchmarks/jd/` 的 J01～J65、京东页面／路由／帮助入口、京东 Adapter、京东测试数据 profile、正式站白名单和京东验收 UI。专用常量不得写进通用 Runner。

## 真实性边界

指导书确认的是页面能力和最终标准，不等于本机已经取得可执行账号、稳定 selector、固定 SKU、隔离库存池、支付／退款模拟器、后台 API 或危险动作授权。缺少其中任一事实时，对应场景保持 `blocked`；本地单元测试、结构化场景、公共正式站只读和 dry-run 都不能冒充交易闭环通过。

## 迭代规则

`.30` 完成功能封装后冻结；现场反馈先复制为 `.31`，后续使用 `.32/.33`。每个问题先分类为通用核心、京东专用、环境／网络／权限或未知待确认。通用补丁只有去除京东常量并独立验证后，才登记为未来统一主线候选。

## 京东 65×5 验收边界

- 批次引擎与尝试证据模型属于通用候选；J01～J65 目录、5 次／325 分母、京东阈值和“电商验收”页面属于京东专用配置层。
- 验收客户端不得手填通过率。verified 尝试必须关联当前包内真实 `run.json`，后端从运行终态、稳定回放、发布门禁、零残留和证据完整率派生指标。
- `bindingStatus=bound` 仍不足以启动尝试；场景必须携带经过审核的 `executablePlan` 且阻塞依赖为空。缺任一条件时保持 blocked。
- 当前 65 个场景全部为 5 次 blocked／unverified。后续现场 AI 只能在取得授权页面事实、账号、沙箱和固定数据后逐场景补充绑定，不得批量删除阻塞或写入虚假 runId。

## 1.30.31 账号态只读验证边界

- 专用账号只用于京东正式消费者站的登录态只读验证；账号、密码、Cookie 原文和明文 storageState 不得写入源码、配置、日志、文档、截图或最终 ZIP。
- 京东验证码、滑块、短信、扫码和设备确认必须由人员在真实浏览器中完成，AI 不得绕过风控。
- 登录态导入前只保留 `jd.com` 及其子域，实际出现的京东子域逐项进入项目允许列表；任何第三方域继续拒绝。
- GUI 使用 Windows DPAPI / CurrentUser 加密保存项目会话。交付封装前必须排除测试生成的 `data`、`artifacts`、服务日志和 `.verification`，不得交付可复用账号态。
- 已验证登录、加密会话导入、账号首页兼容扫描和 Docker Runner 只读断言；没有隔离交易沙箱时，不得扩展到购物车、权益、地址、发票、订单、支付、评价、售后或退款写动作。
