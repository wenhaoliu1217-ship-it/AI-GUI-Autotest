# AIGU-2.3 AI 接入版真实 GUI 自动化测试平台

更新日期：2026-07-22

## 重要变化

本版本已移除前端 Mock 结果生成器。系统现在通过本地 FastAPI 服务调用 Playwright Chromium，真正访问目标网站、执行审核后的步骤和断言，并为每个已执行步骤保存 PNG 截图。

- 未连接执行服务时，GUI 明确报错，不生成成功或失败结果。
- 已删除“制造一个失败结果”开关；最终状态来自浏览器实际执行。
- 无法解析的自然语言会返回错误或人工补充项，不会默认判定成功。
- “截图”按钮打开本次运行实际生成的 PNG 证据。
- 新增“AI 模型设置”入口，支持 OpenAI Responses API 和兼容 Chat Completions。
- AI Key 仅保留在当前网页内存并传给本机后端处理；不落盘、不进入浏览器存储、历史记录或报告，刷新页面即清除。
- 模型生成的计划必须经过封闭动作白名单和 Pydantic Schema 校验，并仍需人工审核后才能执行。
- 新增企业“项目接入”：项目配置、允许域名、运行限制和真实只读兼容性扫描。
- L1 项目可导入 Playwright `storageState`；Cookie/Origin 先做域名校验，再使用 Windows 当前用户 DPAPI 加密，明文不会写入磁盘、报告或前端响应。

## 项目接入与 L1 登录态

1. 点击左侧“项目接入”，填写项目名称、Base URL、允许域名和运行限制。
2. L0 用于公开／免登录页面；L1 用于需要已登录会话的业务页面。
3. L1 可选择由 Playwright 生成的 `storageState.json`，再点击“加密导入登录态”。
4. 系统只展示 Cookie 数量、Origin 数量、域名和过期状态，不展示 Cookie 值。
5. 点击“启动真实只读扫描”；扫描只导航和观察，不点击、不填写、不提交。
6. 选择该项目后新建并执行测试，真实浏览器会加载该项目的登录态和允许域名限制。

登录态使用 Windows DPAPI CurrentUser 加密，只能由导入它的同一 Windows 用户解密。复制到其他电脑或其他 Windows 账号后需要重新导入。产品内交互录制登录态尚未实现。

## 在网页中接入 AI

1. 启动平台后，点击左侧“AI 模型设置”。
2. OpenAI 用户保留“Responses API”和 `https://api.openai.com/v1`；兼容服务请选择“Chat Completions”并填写服务商地址。
3. 填写模型名称和重新生成、从未暴露的新 API Key。
4. 点击“测试模型连接”；成功后点击“使用 AI 新建测试”。
5. 输入自然语言流程，选择“AI 模型规划”，生成后逐步审核，再启动真实浏览器测试。

连接测试和 AI 规划会产生模型调用费用。页面不会保存配置，刷新后需重新填写。已经在聊天、截图或日志中公开过的 Key 必须撤销，不能继续使用。

## Windows 最快运行

1. 完整解压交付 ZIP，不要只复制 `start.bat`。
2. 安装并启动 Docker Desktop，等待 WSL2 Linux Engine 可用。
3. 打开 `Windows一键运行` 文件夹并双击 `start.bat`。
4. 启动器固定使用包内 Python 3.12.10 和 Playwright 1.49.1 Chromium，不要求安装系统 Python。
5. 已存在 `ai-gui-runner:1.30.00` 时直接复用；不存在时从包内离线镜像归档恢复。
6. 浏览器打开实际提示的本地地址；若 8080 已占用，启动器会在 8080～8090 中选择空闲端口。

启动窗口是本地服务的生命周期控制窗口。按 Enter 正常退出或直接关闭窗口时，Windows Job Object 会终止本包 Uvicorn 进程树并释放端口。若需要从另一个窗口停止服务，可双击 `Windows一键运行/stop.bat`；它只在 `server.pid` 中的包路径、便携 Python 路径、进程启动时间和 Uvicorn 命令行全部匹配时停止当前包服务，不会按端口或进程名称影响其他版本。

本交付包的启动过程严格离线，不会执行 `pip install`、`playwright install` 或 `docker build`。若 Python、Chromium 或 Runner 归档缺失，启动器会明确报错，不会从互联网修复，也不会降级到宿主进程执行测试。

便携运行时位于：

```text
Windows一键运行/runtime/
  python/                         # Python 3.12.10 与固定应用依赖
  ms-playwright/                  # Playwright 1.49.1 Chromium 运行时
  images/ai-gui-runner-1.30.00.tar
```

Docker Desktop、WSL2 和 Windows 虚拟化仍是系统级前提，不能作为普通文件随 ZIP 便携启动。本补丁只调整冻结版本的交付兼容性，不改变 `1.30.00` 的业务功能、执行策略或版本需求范围。

运行证据保存在：

```text
Windows一键运行/artifacts/<运行编号>/
  run.json
  events.jsonl
  report.html
  report.md
  trace.zip
  screenshots/*.png
```

## 自然语言格式

当前内置的是透明、确定性的中文规则规划器。推荐使用明确语句并用分号分隔：

```text
在“用户名”输入“admin”；
在“密码”输入“admin123”；
点击“登录”；
确认看到“客户管理”；
截图
```

复杂业务流程可在“AI 模型设置”中接入经企业批准的模型供应商。AI 只负责把文字转换为受约束计划，不会直接宣布测试成功；最终结果仍来自 Playwright 的真实操作和断言。

## 真实执行边界

- 只测试已获授权的 Web 测试环境。
- 首期执行器为 Chromium；不包含小程序或 Windows 桌面自动化。
- 验证码、MFA、SSO 和真实账号必须采用企业批准的测试方案。
- 目标页面发生跨域跳转时，执行器默认拒绝。
- 失败原因属于启发式提示，必须结合截图与 trace 人工复核。

## 公网部署说明

纯静态托管无法在云端启动 Chromium。公网部署必须同时部署 Python 执行服务到允许启动浏览器的 Windows/Linux 主机或容器，并在构建 GUI 时设置 `VITE_API_BASE_URL`。只部署 `dist` 会显示“执行服务未连接”，这是防止伪造结果的设计行为。
