# 1.30.10 目录内 AI 开发强制规则

本文件适用于 `AI-GUI-Autotest/1.30.10` 及其全部子目录。任何 AI、开发者或自动化工具在本目录工作前，必须先阅读本文件、`1.30.10_GAEALaViC专用改动边界与迭代规则.md`、`1.30.10版本更新与需求状态.md` 和仓库根接续说明。

## 1. 版本和修改范围

1. `1.30.00` 是多网站开发的共同通用母版；`1.30.10` 是从它派生的第一个网站专用分支，仅服务 GAEALaViC。
2. 只允许修改用户明确指定的版本目录。处理 `1.30.10` 时，不得回写 `1.30.00`、`1.30.20` 或任何其他版本。
3. `1.30.10` 是冻结的现场交付基线。收到组员现场反馈后，必须先完整复制 `1.30.10` 为 `1.30.11`，再在 `.11` 修改；后续依次使用 `.12`、`.13`。不得用功能改动覆盖 `.10`。
4. 冻结版本只允许明确标注的交付兼容性、安全、封装、校验或文档补丁；任何业务功能变化都必须建立后续版本。
5. 第二个网站的 `1.30.20` 必须从 `1.30.00` 新建，不能从 `1.30.10/.11/.12` 复制。各网站分支不得互相作为母版。

## 2. 修改前强制分类

每个问题在改代码前必须归入以下一类，并在版本状态中记录：

- `通用核心`：不依赖 GAEALaViC 名称、路由、账号、业务对象或页面结构，可由不同网站复用。
- `GAEALaViC 专用`：只为该站的路由、模块、对象、场景、Adapter、Bridge hook 或验收合同服务。
- `环境／网络／权限`：Docker、端口、内网、账号、租户、角色、数据、服务可达性或授权问题。
- `未知待确认`：指导书和现场证据均不足，不能可靠实现或判断。

分类不明时保持 `未知待确认`，不得凭猜测写入通用核心。通用问题可以先在当前网站增量版验证，但要形成独立、无 GAE 常量的可移植补丁；只有用户明确安排主线回合并时，才允许回迁到新的通用母版。

## 3. GAEALaViC 专用边界

GAE 路由、`test001`、租户／密码密钥别名、九模块页面映射、17 个详情页签、HGT 规格、S01～S30、L4 合同、企业 Viewer hooks、目标站状态机和 WebSocket 协议不得硬编码进通用 Runner、通用 Planner、通用证据模型或通用组件执行器。

专用逻辑应放在 `backend/benchmarks/gaealavic/`、GAE 项目 Adapter 模板、`gaealavic_cesium_adapter.js`、GAE 场景绑定配置或同等专用模块中。必须通过既有 Adapter／Bridge／上下文／配置合同接入通用核心。

## 4. 事实、验证和安全

1. 企业未知事实不得编造 selector、无文本图标含义、隐藏文件 input、状态机、WebSocket 消息、账号权限、对象接口、下载结构或成功结论。
2. 未在真实目标站执行的结果必须保持 `unverified`、`blocked` 或 `dry_run_only`。本地测试、公共站测试、Docker 测试和 dry-run 均不能替代企业站通过结论。
3. 密码、Cookie、Token、真实密钥、认证头和敏感业务数据不得写入源码、配置、日志、截图、报告或文档；只保存运行时密钥引用和脱敏证据。
4. 删除、运行、训练、批量修改、上传等副作用必须继续经过作用域、权限、确认、命名和清理门禁，不得为了跑通现场流程绕过。

## 5. 修改和发布完成条件

每次修改必须同步更新：

- 当前增量版本的版本状态文档；
- GAEALaViC 专用改动边界文档；
- 根接续说明中的版本关系、完成状态、阻塞和下一步；
- 与修改对应的测试和验收证据。

交付继续遵守便携离线标准：企业 IT 一次性预置 Docker Desktop、WSL2／Hyper-V 和 Linux Engine；版本包自带 Python、固定依赖、Chromium 和离线 Runner 镜像；端口生命周期使用 Job Object、`server.pid` 与 `stop.bat`。重新发布时必须从干净目录封装、全新解压、双击验收、检查端口和容器清理，并更新 ZIP 大小与 SHA-256。
