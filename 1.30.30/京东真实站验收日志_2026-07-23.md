## GUI 功能缺陷

### P0-1 本地规则规划器不理解否定语义

输入“不登录、不填写、不点击任何会产生账户或交易副作用的控件”时，规划器按关键词把“不填写”生成为 `fill`，把“不点击”生成为 `click`。当前警告门禁阻止了审核和执行，因此没有造成副作用，但计划语义本身不合格。

修复要求：规划前识别否定／禁止句，将其映射为约束而不是动作；Commerce 项目中的禁止动作必须参与计划校验，生成任何冲突步骤时直接拒绝计划。

### P0-2 可见性断言存在多匹配假阴性

运行 Observation 明确包含可见的 `h1 京东`、链接“京东”和标题，但 `visible(text=京东)` 返回 `false`。当前实现对 `get_by_text()` 的结果直接取 `.first.is_visible()`；第一个匹配隐藏时会忽略后续可见匹配。

修复要求：可见性断言应判定“至少一个匹配可见”，或在多匹配时要求用户／规划器提供 role、heading、label、test-id 或 CSS 等唯一定位依据，并在报告中记录匹配数和所选依据。

### P0-3 隐私门禁对请求 URL 产生大量假阳性

PII 检测把京东请求 URL／查询参数中的长数字识别为银行卡号，共 28 项，使发布门禁失败。门禁只保存命中哈希是正确的，但原始运行证据仍保存完整失败请求 URL，报告最小化不足。

修复要求：PII 扫描区分业务字段与 URL 技术参数，银行卡检测加入 Luhn、字段上下文和去重；失败请求证据默认仅保留 origin、path 模板、状态码和 URL 哈希，对 query/token/设备标识做剥离或遮罩。

### P1-1 AI 连接与长计划生成稳定性不足

同一配置可完成最小连接测试，但长计划生成连续三次返回上游 HTTP 502；其他轮次中最小连接也偶发失败。该问题可能来自模型供应商稳定性、代理兼容或超时策略，不能归因于京东。

修复要求：分别记录供应商 HTTP 状态、超时阶段和可重试分类；对只读计划允许有限重试与明确降级，不得把最小连接成功等同于计划接口可用。

## 网站／环境限制

- 京东首页的若干匿名动态 API 返回 403，属于正式站风控、签名或匿名资源限制；不能通过绕过风控解决。
- 多轮兼容扫描发现页数变化，说明正式站内容和请求具有动态性；验收应使用稳定核心锚点，不能以动态推荐内容作为唯一断言。
- 无企业授权账号和隔离交易沙箱，因此账号、购物车、订单、支付、退款、售后、并发库存和清理闭环全部未验证。
