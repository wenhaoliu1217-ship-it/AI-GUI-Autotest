## Versions

详见 [`1.20.00功能说明.md`](./1.20.00/1.20.00功能说明.md)。

### 1.25.00

冻结历史版本。增加项目／环境／场景、兼容性扫描、Run Orchestrator、逐步 DOM Agent、截图视觉适配、结构化 Finding、人工审核、Playwright 代码生成和完整结果管理。

详见 [`1.25.00版本更新与需求状态.md`](./1.25.00/1.25.00版本更新与需求状态.md)。

### 1.30.00

冻结的通用能力基线。FR-01～FR-11 的约定单用户功能范围已完成，包含目标优先 Agent、业务上下文、真实自适应回放、Docker 隔离、Canvas App Bridge、Cesium 参考适配、非 DOM 证据和结构化 Finding。

详见 [`1.30.00版本更新与需求状态.md`](./1.30.00/1.30.00版本更新与需求状态.md)。

### 1.30.10

当前权威开发版本。完整继承 `1.30.00`，用于 ER-07、GAEALaViC／首个企业测试网站适配、授权数据与角色矩阵、30 场景×5 次重复基准和企业级验收。ER-08 与第二个非 Cesium 业务网站验证归属后续 `1.30.20`。

详见 [`1.30.10版本更新与需求状态.md`](./1.30.10/1.30.10版本更新与需求状态.md)。

## Release Packaging Gate

从后续版本开始，Windows 交付包必须满足“解压后双击运行”，该要求是发布硬门槛，不得以开发机原目录启动成功代替：

- 企业 IT 只需一次性预置并启用 Docker Desktop、WSL 2／Hyper-V 和 Linux Engine；这些系统级能力不打入交付包。
- 交付 ZIP 必须自带便携 Python、Playwright Chromium 及其运行依赖、离线 Docker Runner 镜像和导入脚本；不得要求使用者联网执行 `pip`、`npm`、Playwright 下载或 `docker build`。
- 使用者把 ZIP 解压到任意全新目录后，只需双击 `Windows一键运行\start.bat`；启动器负责本地依赖检查、离线镜像导入、端口选择、服务启动和浏览器打开。
- 发布验收必须在断网条件下，把最终 ZIP 解压到不含旧 `.venv`、`node_modules`、运行数据或预装 Runner 镜像的干净目录，再从解压目录双击 `start.bat`。验收至少记录健康地址、退出码、便携运行时来源、Chromium 来源、Runner 镜像导入结果和 ZIP SHA-256。
- 启动失败时窗口必须保留，明确区分系统预置缺失、Docker Engine 未运行、包文件缺失、端口耗尽和服务启动失败；不得闪退，也不得回退到宿主进程绕过容器隔离。
- `start.bat` 启动的 API、浏览器辅助进程和本版容器必须绑定启动器生命周期；用户正常关闭启动命令窗口后，本次服务必须停止并释放监听端口。交付包还必须提供同目录 `stop.bat` 作为异常退出兜底。
- `stop.bat` 和同版本重启清理必须通过版本目录、PID 记录、进程可执行文件／命令行及容器标签共同校验归属，只能停止由当前解压目录、当前版本启动的遗留进程和容器；不得按端口号、进程名或模糊匹配杀死其他版本服务及普通进程。
- 发布验收必须覆盖正常关闭释放端口、异常关闭后 `stop.bat` 释放、同版本遗留后重启自清理，以及两个版本并行时互不终止。PID 文件必须防止复用误杀，并在确认进程退出后删除。
- 冻结版本禁止新增或改变业务功能，但允许修复启动器、离线依赖、封装、校验、安装兼容性和安全问题。此类变更必须标记为“交付兼容性补丁”，重新执行干净解压断网验收并更新压缩包与校验值，不改变原版本的功能范围。

## Repository Policy

本仓库不提交虚拟环境、`node_modules`、构建产物、运行数据、截图、Trace、日志、登录态、DPAPI 文件、API Key、密码、Cookie、Token 或内网地址。它们必须在本地或受控交付渠道中管理。

只可对已获授权的测试系统运行本项目。自然语言中的退款、支付、删除、发布等目标不构成执行高风险动作的授权。
