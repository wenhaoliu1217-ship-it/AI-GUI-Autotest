# 1.33.00 通用能力边界与验证约束

## 当前目标

`1.33.00` 的通用执行链必须能够在普通网页、表单页面、SPA 和开放 Shadow DOM 页面上工作。Cesium/仿真能力只能通过专项适配器增加额外证据，不能把专项选择器、路由或全局对象写进通用观察、定位和执行逻辑。

## 四段通用契约

### 决策门禁（Decision Gate）

模型输出通过结构化 Schema 后，还要经过 `planning/decision_gate.py` 的通用预执行审计。它不读取 Cesium 规则，只检查四类可迁移事实：

- 当前观察是否存在，以及定位目标是否出现在有限 DOM/Accessibility 摘要中；
- 动作是否具备执行器所需的结构化目标；
- 同一动作是否在没有进展后重复提出；
- 最近一步失败或无进展时，模型是否错误地宣称任务完成。

审计结果只有三种：`pass`、`warn`、`block`。`warn` 会进入运行证据并继续交给专项安全策略；`block` 会转为暂停状态，不进入浏览器执行器。该设计吸收了 Playwright MCP 的结构化观察、Stagehand 的语义动作回退、OpenAdapt 的“不确定就暂停”和 BrowserGym/AgentLab 的轨迹评估思想。

| 阶段 | 当前入口 | 通用输入 | 输出与停止条件 |
| --- | --- | --- | --- |
| 观察 | `ObservationCollector.capture` | 页面 URL、标题、DOM/ARIA、页面健康、请求和错误 | 脱敏 `Observation`；没有完整页面事实时不能假装完成 |
| 定位与规划 | `resolve_locator`、`AgentScenario`、`AgentDecision` | 当前观察、自然语言目标、历史轨迹 | 一次只产生一个可审核动作；语义定位失败时按候选策略回退，仍不唯一则停止 |
| 执行 | `prepare_action`、`run_plan`、`run_agent_plan` | 已校验的 `Step` | 执行前检查可见、启用、稳定、未遮挡；动作后采集证据 |
| 验证与恢复 | `StepResult`、checkpoint、recovery | 动作前后观察和历史 | 目标证据不足时重新观察；只读重试前重新采集有限页面事实；状态不一致或副作用无法确认时暂停，不盲目重放 |

## 专项适配器规则

- 通用观察器默认不携带任何 Cesium 选择器。
- `CanvasAppBridgeAdapter` 只能通过 `observation_priority_selectors` 提供可选提示。
- 通用确认策略只处理通用动作；网站专项确认规则通过执行组合层 callback 注入，普通模块不直接导入 Cesium 策略。
- `AIAgentPlanner` 只调用 `SiteDecisionStrategy` 接口；Cesium 的确定性恢复、视觉副作用校验和提示词规则由 `CesiumDecisionStrategy` 延迟加载。
- `CesiumBridgeAdapter` 和 `GAEALaViCCesiumBridgeAdapter` 负责场景状态和专项副作用校验；普通网页不会进入这些校验路径。
- 任何网站特有的 URL、元素 ID、按钮类名、加载判断都必须进入适配器或专项基准目录。

## 1.33.00 的两个本地通用基线

- `/`：普通表单、登录、选择框、动态表格和状态统计。
- `/shadow.html`：开放 Shadow DOM、插槽、标签/可访问名称和缺失资源诊断。

两页的任务都先标记为“尚未实测”。只有真实 Playwright 回归产生动作前后证据后，才能把任务改为通过；静态目录检查或 API 合同检查不能改变该状态。

## 开源参考项目的首批吸收点

- Playwright MCP：以 Accessibility/DOM 事实作为第一观察来源。
- Stagehand：保留“语义动作 + 确定性 Playwright 执行”的混合边界；模型不能直接绕过安全检查。
- OpenAdapt：沿用检查点、动作后验证和不确定时暂停的原则。
- BrowserGym、AgentLab、WebArena、OSWorld：后续用于扩充跨页面和跨环境回归分母，而不是直接替换当前执行器。
- TestZeus Hercules：只作流程设计参考；其 AGPL-3.0 代码不在许可证评估完成前进入产品。
